- **Process (settled at charting)**:
  - No scoring, no pre-filtering — every PR is decided individually, oldest first.
  - One PR per **fresh worker** iteration (see Execution architecture below); the grind ticket spans many iterations and is never "resolved" until the list is complete. Each iteration updates exactly one list item.
  - Cherry-pick hygiene: `git cherry-pick -x` (original author/message preserved + traceability line). Push `mitaka/backport` after every landed PR.
  - Append-only: never rebase `mitaka/backport`. The collision-forecast dry-run (ticket 02) runs on a throwaway branch only.
  - Validation: unit tests on jetson-222 (recipe in the setup ticket's Answer) + mandatory in-session manual review of the collision area when the PR touches a wtdcode-patched file.
- **Already-in-backport check**: some official fixes may exist re-implemented in wtdcode's own history (e.g. the hybrid-allocator KV recovery). Patch-id/`git cherry` equality is NOT sufficient (verified: reports 0 despite known re-implementations) — use the **semantic already-present check** defined in the grind ticket's Standing rules.
- **Execution architecture (ratified 2026-09-04)**: main session = orchestrator only; each PR is executed by a **fresh `worker` subagent with `context: fresh`** (no inherited conversation — inherited context caused role-confusion in the oracle trial), strictly sequential (one branch writer; Jetson model server concurrency limit). Worker reports structured `{pr_sha, decision, new_sha?, reason?, env_impact?, collision_review_done?, tests, pushed}`; orchestrator audits and is the single writer of tracker files. Default batch: 5 PRs per "go", report between batches.
- **Future sweeps (ratified 2026-09-04)**: wtdcode updates land in `mitaka/backport` as **merge commits** (append-only-safe); every sweep records its wtdcode base SHA in the map.
- **Security commits** in range (#54353 cache_salt DoS, #54684, #54632) land late under oldest-first — user accepted (2026-09-04).

- **Skills to consult**: `jetson-network-check` before SSH work; `vllm-dsv4-wtdcode-build` only if an image build is ever decided (see fog). Mac-side repo operations follow the repo AGENTS.md (uv/.venv).
