## Execution architecture (ratified 2026-09-04)

- **Main session = orchestrator only.** It composes a self-contained brief per PR — official sha + subject, hot/cold flag + conflict files from the heat-map, the standing rules below, the jetson-222 recipe from ticket 01's Answer, and the report contract — and dispatches a **fresh `worker` subagent with `context: fresh`** (no inherited conversation; inherited context caused role-confusion in the oracle trial). Never parallel: one branch writer, and the Jetson model server accepts limited concurrent requests.
- **Worker = exactly one PR.** Executes the recipe and standing rules, then reports a structured result: `{pr_sha, decision: picked|skipped|partial, new_sha?, reason?, env_impact?, collision_review_done?, tests: {ran, passed, skipped}, pushed}`.
- **Orchestrator audits** (git log, tests summary) and is the **single writer** of tracker files (this checklist + `outcomes.log.md`).
- Continuous auto-grind (standing order 2026-09-05): rounds run back-to-back without asking "go"; report only on escalations/halts or when the user asks.

## Standing rules (ratified 2026-09-04)

- **Semantic already-present check** (every hot PR): `git log -p c01b50e390..3bec275739 -- <touched files>` and an explicit "same fix, different shape?" judgment. Patch-id/`git cherry` equality reports 0 matches despite known wtdcode re-implementations — it is not sufficient.
- **Skip vocabulary**: `→ skipped: semantically present in wtdcode as <sha>` · `→ partial/skip: needs post-cutoff #XXXX` · `→ skipped: <ordinary reason>`.
- **Security commits** #54353 (cache_salt DoS), #54684, #54632 land late under oldest-first — user accepted this (2026-09-04); no exception.
- **C++/CUDA caveat**: the jetson test image's prebuilt extensions are from d4d703caf — Python-level tests only are meaningful. A PR touching C++/CUDA/CMake gets flagged for an image rebuild instead of trusted test results.
- **Outcomes log**: append-only, one line per decided PR — `<official-sha> | picked|skipped|partial | <new-sha|reason> | env-impact: none|<deps changed>`. This checklist's `[x]` is only a progress index.
- **Report-verification gate** (added 2026-09-04 after first fabricated worker report): before any push, the orchestrator verifies the reported landing sha exists on jetson (`git show -s <new_sha>`); a missing sha ⇒ the report is fabricated ⇒ re-dispatch the item to a fresh worker once; a second fabrication ⇒ escalate. Tip checks after push stay mandatory.
- **Conflict playbook** (ratified 2026-09-04; review-sub-agent check added 2026-09-04): on a cherry-pick conflict, the worker judges location. Trivial conflict **outside wtdcode-functional code** → worker hand-merges in-session and shows the full merged diff in the report. Conflict **inside wtdcode-functional code** (model registrations, kernel glue, patch-only helpers) → worker stops, records both sides + a proposed resolution, reports `CONFLICT`; the user decides. **In both paths the orchestrator double-checks any conflict resolution with a fresh review sub-agent (`oracle`, context: fresh)** — before tests/push for hand-merges, or before presenting to the user for proposed resolutions — verifying the resolution preserves both upstream intent and wtdcode semantics with no lost hunks. The review verdict is recorded in the report/outcome line.
- **Writer hygiene** (added 2026-09-04 after the four-unexplained-picks incident): every worker repo command must run inside `ssh jetson-222 '...'` — no local git on the Mac, ever. Worker asserts the branch tip equals the orchestrator-provided expected tip after reset before picking. Orchestrator pushes with `--ff-only` and verifies `ls-remote` tip == landed sha; any unexplained divergence ⇒ halt the grind immediately.
